# Модели данных

## Хранение

Домен-типы (`Account`, `Envelope`, `UserProfile`) — vendor-нейтральные: `createdAt`/`updatedAt` — `number` (epoch ms).
Драйвер хранилища выбирается по `VITE_STORAGE_DRIVER`: `firestore` (production) или `local` (dev, localStorage).
Схема ниже описывает представление в Firestore-адаптере; local-адаптер хранит те же поля в JSON.

## Firestore коллекции

### `users/{userId}`
```typescript
interface UserProfile {
  email: string;
  createdAt: number;          // epoch ms
  updatedAt: number;          // epoch ms
}
```

**Планируется:** `displayName`, `currency`

### `users/{userId}/accounts/{accountId}`
```typescript
interface Account {
  name: string;             // "Наличные", "Карта", etc.
  balance: number;          // текущий баланс в целых рублях
  creditLimit?: number;     // для кредитных карт (в рублях); если есть — тип = card
  icon?: string;            // emoji, по умолчанию '💳'
  includeInBalance: boolean; // участвует в общем балансе
  currency: string;         // 'RUB' (всегда, post-MVP — мультивалютность)
  sortOrder: number;        // хранится, но сортировка по createdAt
  createdAt: number;          // epoch ms
  updatedAt: number;          // epoch ms
}
```

Тип счёта не хранится — выводится:
- `creditLimit` присутствует → `card`
- иначе → `cash`

**Планируется:** `color`

### `users/{userId}/envelopes/{envelopeId}`
```typescript
interface Envelope {
  name: string;             // "Резервы", "Отпуск", etc.
  balance: number;          // текущий баланс в целых рублях
  isGoal: boolean;          // true — конверт-цель (target обязателен)
  target?: number;          // целевая сумма (в рублях); обязательна при isGoal=true
  icon?: string;            // emoji, по умолчанию '✉️'
  isBuiltIn?: boolean;      // true только для Резервов (нельзя удалить)
  sortOrder: number;        // хранится, но сортировка по createdAt
  createdAt: number;          // epoch ms
  updatedAt: number;          // epoch ms
}
```

Поле `type` отсутствует. Системный конверт идентифицируется через `isBuiltIn: true`.

#### ХаниМани — вычисляемое значение (не документ)

ХаниМани не хранится в Firestore. Рассчитывается на клиенте при каждом рендере:

```
ХаниМани = Σ(account.balance | includeInBalance=true)
           − Σ(envelope.balance | isBuiltIn=true)    // Резервы
           − Σ(envelope.balance | isBuiltIn≠true)    // пользовательские конверты
```

Изменяется автоматически при любом изменении счетов или конвертов. Для транзакций без конкретного конверта: `envelopeId: null` = ХаниМани.

#### Виды конвертов (Firestore-документы)

**Системный** (ровно 1, неудаляемый):
- **Резервы** — `isBuiltIn: true`, `isGoal: false`. Создаётся автоматически при регистрации.

**Пользовательские** (0..20 суммарно):
- Обычный конверт — `isGoal: false`, `target` не задан
- Конверт-цель — `isGoal: true`, `target` обязателен; UI показывает прогресс-бар

Лимит: **20 пользовательских конвертов**. Проверяется в `envelopeStore.createEnvelope`.

#### Палитра иконок
Первая иконка `✉️` — дефолт для новых конвертов (`DEFAULT_ICON`). Полный список — `ICONS` в `src/components/envelopes/constants.ts`.

#### Прогноз Резервов (вычисляемый)
Не хранится — рассчитывается на клиенте. Горизонт: до **12 месяцев вперёд** (аналогично оригинальному HM).
```
дефицит/профицит = balance.reserves
  + SUM(transactions.mode=plan.income)
  - SUM(transactions.mode=plan.expense)
  - SUM(plannedTransfers.toReserves)
  + SUM(plannedTransfers.fromReserves)
```
⚠️ Формула проектная — на этапе 6 потребуется режим Факт/План у транзакций (см. ниже).

### `users/{userId}/transactions/{transactionId}` — частично реализовано (2026-09-11)

Текущая реализация (Этап 4 завершён, 2026-09-11):

```typescript
type TransactionType = 'income' | 'expense' | 'transfer';
type TransactionMode = 'fact' | 'plan';
type RepeatFrequency = 'day' | 'week' | 'month' | 'year';

interface TransactionRepeat {
  frequency: RepeatFrequency;   // + interval: 1..6 дней, 1..4 недель, 1..6 месяцев (дробный 1.5)
  interval: number;
  until?: number | null;        // «Повторять до:», null = бесконечно
  weekendMode?: 'workdays' | 'weekends';  // по будням / по выходным (day/1)
}

interface Transaction {
  type: TransactionType;        // доход / расход / перевод
  mode: TransactionMode;        // Факт (влияет на балансы) / План (не влияет)
  date: number;                 // epoch ms (день транзакции)
  amount: number;               // > 0, знак определяется типом
  category: string;             // свободная строка, создаётся на ходу; у переводов — «Перевод»
  description?: string;         // из natural language (после парсинга)
  accountId: string;            // счёт (для transfer — источник при переводе счетов)
  envelopeId: string | null;    // null = ХаниМани; при transfer-конвертов — источник
  toAccountId?: string;         // перевод между счетами — получатель
  toEnvelopeId?: string;        // перевод между конвертами — получатель
  seriesId?: string;            // повторяющаяся серия: общий id у всех экземпляров
  repeat?: TransactionRepeat;   // правило серии (дублируется в каждом экземпляре)
  createdAt: number;            // epoch ms
  updatedAt: number;            // epoch ms
}
```

**Влияние на балансы** (transactionStore, только `mode: 'fact'`):
- расход — счёт `−amount`, конверт `−amount`; доход — счёт `+amount`, конверт `+amount` (в ХаниМани — только счёт)
- перевод между счетами — источник `−amount`, получатель `+amount`
- перевод между конвертами — конверт-источник `−amount`, конверт-получатель `+amount`
- редактирование/удаление откатывают старые дельты; ХаниМани вычисляется из балансов и отдельно не хранится

**Повторяющиеся серии**: материализуются как N план-транзакций (общий `seriesId`,
даты из `repeatUtils.generateRecurringDates`; горизонт 12 месяцев или `until`).
Месяцы/годы считаются от базовой даты (день серии сохраняется: 31.01 → 28.02 → 31.03).
Правка серии: «Только эту» / «Эту и будущие» (пересоздание серии от этой даты, прошлые не трогаются).
Редактор категорий: переименование категории во всех транзакциях (batch update).

Планируемые расширения (Этап 5+): фильтры списка, статус неподтверждённой, тэги.

### Natural language парсинг

Формат ввода: `5*250 яблоки (комментарий)` (`src/lib/parseTransactionInput.ts`)

- `5*250` = 5 единиц × 250 = 1250; поддержка запятой: `1,5*100`
- `яблоки` = описание
- `(комментарий)` = игнорируется, заметка (только хвостовые скобки)
- Строка без суммы → вся строка — описание (amount: null)

## Индексы Firestore

1. `transactions` — по `date` (desc) + `accountId`
2. `transactions` — по `category` + `date`
3. `transactions` — по `isRecurring` + `date`
4. `transactions` — по `envelopeId` + `date`
5. `transactions` — по `type` + `date`
6. `transactions` — по `mode` + `date`

## Хранение сумм

Все суммы хранятся в **целых рублях** (шаг 1). Копейки не используются.
Отображение: число без дробной части.

⚠️ После реализации транзакций — убедиться, что `amount`, `TransactionItem.unitPrice` и `Envelope.balance` не записаны «в копейках».
