# Обоснование стека

## React 19 + Vite

| Критерий | Выбор | Альтернативы |
|----------|-------|-------------|
| Сборка | Vite | CRA (устарел), Next.js (избыточен для SPA) |
| UI | React 19 | Svelte, Solid (меньше экосистема) |
| Роутинг | React Router 7 | TanStack Router |
| Язык | TypeScript | JavaScript (меньше safety) |

**Почему не Next.js**: нам не нужен SSR, приложение полностью клиентское.
GitHub Pages не поддерживает SSR. SPA с Vite — оптимальный выбор.

## Tailwind CSS v4

- Быстрая разработка UI без кастомных CSS-файлов
- Отличная интеграция с React
- Маленький итоговый бандл (purge)
- v4 — конфигурация через CSS (`@theme`), без tailwind.config.js

## TypeScript 7 (нативный компилятор)

- С 2026-09-11 — TypeScript `7.0.x` (native port, Go): `tsc -b` на порядок быстрее
- API не используется — только CLI, поэтому переход с 6.x прошёл без правок кода
- Strict mode сохранён

## pnpm (package manager)

- Скорость и экономия диска через content-addressable store (symlinked `node_modules`)
- Строгая структура `node_modules` — поймает обращения к необъявленным зависимостям
- `pnpm-workspace.yaml` — управление postinstall-скриптами (`allowBuilds`) и supply-chain политиками (`minimumReleaseAge`) из коробки
- `packageManager` в `package.json` фиксирует версию через corepack
- Миграция с npm: 2026-09-11, `package-lock.json` → `pnpm-lock.yaml`
- CI: `pnpm/action-setup@v4` + `setup-node` с `cache: pnpm` + `pnpm install --frozen-lockfile`

## GitHub Pages + Actions (CI/CD)

- Хостинг статики: GitHub Pages (бесплатно)
- Кастомный домен: https://money.vitalik.dev (CNAME в репозитории)
- CI/CD: GitHub Actions — автоматическая сборка и деплой при пуше в `master`
- Воркфлоу: `actions/checkout` → `pnpm/action-setup` → `setup-node` → `pnpm install --frozen-lockfile` → `pnpm run build` → `actions/deploy-pages`
- Превью продакшен-сборки локально: `pnpm run preview`

## Firebase

| Сервис | Назначение | Бесплатный лимит |
|--------|-----------|-----------------|
| Firestore | База данных | 1GB, 50k reads/day, 20k writes/day |
| Auth | Аутентификация | Безлимит (email/password) |
| Hosting | (не нужен — GitHub Pages) | — |

**Альтернатива**: Supabase — тоже имеет бесплатный tier, но требует больше конфигурации.
Firestore проще для старта: встроенная офлайн-персистентность, реальное время, меньше бойлерплейта.

## Backend-абстракция (anti vendor-lock)

С 2026-09-11 приложение не зависит напрямую от Firestore SDK — только от собственного интерфейса `src/lib/backend/`:

```
src/lib/backend/
├── types.ts            # Backend, AuthProvider, Repository, BackendError, User
├── firestore/          # production-адаптер (Firebase SDK, ленивая инициализация)
│   ├── firebase.ts     # getFirebase() — memoized init; вызывается только при операциях
│   ├── dataAdapter.ts  # accounts/envelopes repositories, Timestamp ↔ number на границе
│   └── authAdapter.ts  # Firebase Auth → нейтральный User; ошибки → BackendError
├── local/
│   └── adapter.ts      # dev-адаптер: данные в localStorage + фейковая auth
└── index.ts            # выбор драйвера по VITE_STORAGE_DRIVER (local | firestore)
```

- **Доменные типы** (`Account`, `Envelope`) нейтральны: `createdAt`/`updatedAt` — `number` (epoch ms), без `Timestamp` из firebase
- **Выбор драйвера**: `.env.development` задаёт `local` (dev без Firebase и сети); production-сборка — `firestore`; override в дев-режиме — `VITE_STORAGE_DRIVER=firestore pnpm run dev` (process env приоритетнее `.env`)
- **`accountService`/`envelopeService`** остались фассадами с прежним API — stores не знают о бэкендах
- **`authStore.logout`** сам сбрасывает user в state (Firebase полагался на `onAuthStateChanged`, local — нет)
- **Бонус**: ленивая инициализация Firebase — дев-разработка работает без `.env`; e2e local-проект гоняется на localStorage без Firebase и cleanup
- Подмена адаптера при тестах: сторы мокают фассады, поэтому юнит-тесты не зависят от драйвера

## react-number-format

Используется для числовых инпутов с форматированием:
- Разряды через пробел (1 000, 100 000)
- Только целые рубли (`decimalScale={0}`)
- `allowNegative` — `true` для баланса счёта/конверта, `false` для кредитного лимита и целевой суммы
- Обёртка `MoneyInput` (`src/components/ui/MoneyInput.tsx`) инкапсулирует общие пропы

## Zustand (state manager)

- Минимальный API (нет reducers, actions, dispatchers)
- Не требует Provider
- Работает вне React-компонентов
- TypeScript-first

## Vitest + Testing Library (unit-тестирование)

| Инструмент | Назначение |
|-----------|-----------|
| Vitest | Test runner (нативный Vite-плагин, не требует Babel) |
| @testing-library/react | Рендер компонентов в jsdom |
| @testing-library/jest-dom | Матчеры (toBeInTheDocument, toHaveTextContent) |
| @testing-library/user-event | Симуляция событий (click, type, tab) |
| jsdom | Браузерное окружение для Node.js |

- **Конфиг**: `vitest.config.ts` (jsdom, setup-файл)
- **Setup**: `src/test/setup.ts` (jest-dom + глобальный afterEach(cleanup))
- **137 тестов** (17 файлов): stores, components, pages
- **CI**: `pnpm test` перед `pnpm run build` — если тесты падают, деплой блокируется
- **Static analysis**: только `tsc -b` (strict mode), ESLint/Biome не используются
- **Паттерн моков**: Firebase модули на уровне `vi.mock`, Zustand stores через `vi.hoisted()`
