# Техническое задание: hmoney

## 1. Назначение

Личное веб-приложение (SPA + PWA) для ручного учёта личных финансов — упрощённый аналог
HoneyMoney (https://hmbee.ru). Делается для себя, **не для распространения**: онбординг,
партнёрская программа и маркетинг — вне рамок проекта.

Домен: https://money.vitalik.dev

## 2. Принципы (унаследованы от философии ХаниМани)

- Ручной учёт by design — без синхронизации с банками (см. [Философия](../Источники/ХаниМани%20—%20Философия%20%28почему%20нет%20автоматизации%29.md))
- Планирование будущего (cashflow-прогноз) важнее ретроспективы
- Конверты снимают ментальную нагрузку: система подсказывает «сколько можно тратить»
- UI адаптивный на каждом этапе (мобильные устройства — через responsive, отдельный мобильный UI не делается)
- Без онбординга, рекламы и партнёрских программ

## 3. Карта функций HoneyMoney → hmoney

Легенда: ✅ реализовано · **MVP** — этап 4–8 · **post-MVP** · ❌ out of scope
Источники: [Карта функций (бандл демо)](../Источники/ХаниМани%20—%20Карта%20функций%20приложения%20%28бандл%20демо%202026-09%29.md), [Возможности и тарифы](../Источники/ХаниМани%20—%20Возможности%20и%20тарифы%20%28актуализация%202026-09%29.md)

### 3.1 Аутентификация
- ✅ Регистрация/вход/выход (email + пароль), защита маршрутов
- ✅ Профиль пользователя в Firestore (`users/{uid}`)

### 3.2 Счета
- ✅ CRUD счетов; типы: наличные (по умолчанию) / кредитная карта (через `creditLimit`)
- ✅ Отрицательный баланс, флаг «исключить из общего баланса»
- ✅ Кредитный лимит → «доступно» (лимит − использовано)
- **MVP**: переупорядочивание счетов (drag или кнопки) — в ХаниМани есть «Изменить порядок»
- **post-MVP**: категории счетов (настраиваемые, сортируемые); будущий баланс счёта («Сумма и Будущий Баланс» по планам); импорт балансов из CSV

### 3.3 Конверты (Счета и Конверты)
- ✅ Вычисляемый ХаниМани (Σ включённых счетов − Σ конвертов); системный конверт Резервы (`isBuiltIn`)
- ✅ Пользовательские конверты: обычные Фонды и Цели (`isGoal` + `target`), лимит 20
- ✅ Прогресс-бар для целей; сворачиваемые группы
- **MVP**: переводы **между конвертами** (например, из ХаниМани/Резервов в Фонд «Налоги»)
- **post-MVP**: виртуальные счёта-цели как отдельные объекты («Нужно накопить → откладывать X в месяц»); расчёт темпа накопления «в месяц/неделю»

### 3.4 Транзакции (Этап 4 — MVP)
- **MVP**: CRUD транзакций; поля: дата, сумма, категория, описание, счёт, конверт
- **MVP**: типы: доход, расход, перевод; статус (неподтверждённая) отдельным флагом
- **MVP**: режимы Факт / План (план не влияет на балансы, участвует в прогнозе)
- **MVP**: natural language input `5*250 яблоки (комментарий)` — количество × цена
- **MVP**: **повторяющиеся транзакции** — периодичности: день/неделя/месяц/год; каждые N дней (2–6),
  N недель (2–4), N месяцев (2–4), 1.5 месяца, полгода, по будням, по выходным;
  «Повторять до:» или бесконечно; правка серии: «Только эту» / «Эту и будущие»
- **MVP**: переводы **между счетами** (в противовес переводам между конвертами — см. 3.3)
- **MVP**: фильтрация (дата, счёт, конверт, тип, категория, описание, неподтверждённые)
- **MVP**: категории создаются на ходу (редактор категорий, категории/подкатегории — плоский список категорий в MVP, подкатегории post-MVP)
- **MVP**: массовые операции — удаление выбранных (для чистки после перерыва)
- **post-MVP**: шаблоны транзакций (быстрый ввод из шаблона)

### 3.5 Календарь (Этап 5 — MVP)
- **MVP**: месячная сетка (недели × дни), транзакции по дням
- **MVP**: быстрое добавление кликом по дню (модал с суммой+описанием в одном поле)
- **MVP**: фильтры: категории/конверты/счета/типы, поиск по описанию, неподтверждённые
- **MVP**: отображение дня «кратко» / «подробно»
- **MVP**: drag-and-drop перемещение/копирование (копирование с зажатым Alt/Ctrl)
- **MVP**: сводка за месяц: доходы, расходы, разница, «не потрачено» / «перепотрачено» (%, Alt+Z)
- **MVP**: Net Worth («Всего денег») в хедере на всех страницах

### 3.6 Список (Этап 5/6 — MVP)
- **MVP**: таблица транзакций с фильтрами (те же, что в календаре) и пагинацией/ленивым списком
- **MVP**: группировка/сортировка по дате; массовое удаление
- **post-MVP**: тэги транзакций (поиск по тэгу — механизм импорта ХаниМани строит на этом)

### 3.7 Прогноз Резервов (Этап 6 — MVP)
- **MVP**: расчёт дефицита/профицита Резервов на год вперёд: баланс Резервов,
  плановые доходы/расходы, запланированные переводы в/из Резервов
- **MVP**: подсказка «перевести X из ХаниМани в Резервы» при дефиците; Alt+X
- **MVP**: «оптимальный баланс» Резервов = достаточно на все запланированные расходы

### 3.8 Отчёты (Этап 6 — MVP)
- **MVP**: отчёт за период: доходы / расходы / разница, среднее «в месяц», расходы как % от доходов
- **MVP**: гранулярность: по месяцам / по годам / свой период / с начала учёта
- **MVP**: фильтры «включить/исключить» категории и счета
- **MVP**: отчёт по категориям (в MVP — таблица/bar; treemap — post-MVP)
- **MVP**: Net Worth — общее состояние
- **post-MVP**: сравнение периодов (compare_periods); treemap статистика категорий

### 3.9 Настройки (Этап 8 — MVP)
- **MVP**: минимальные настройки: начало недели (Пн/Вс), основной счёт по умолчанию
- **post-MVP**: основная валюта и мультивалютность (калькулятор курсов — отдельный блок ХаниМани)

### 3.10 Платформа
- ✅ SPA (GitHub Pages), адаптивный Tailwind-интерфейс
- **MVP** (Этап 7): PWA — манифест, иконки, офлайн-режим (service worker), оффлайн-ввод с последующей синхронизацией
- **post-MVP**: «Доступна новая версия» prompt (SW update), iOS install prompt
- ❌ Отдельный мобильный UI, партнёрская программа, онбординг, продажа подписки

### 3.11 Явно вне рамок (❌)
- Синхронизация с банками / SMS-разбор / автокатегоризация — анти-философия продукта
- Оплата счетов из приложения
- Напоминания о платежах (push/e-mail) — по необходимости позже
- Партнёрская программа, отзывы, маркетинг

### 3.12 Post-MVP сводка
Импорт CSV (транзакции и балансы) · категории счетов · будущий баланс счёта · сравнение периодов ·
treemap · подкатегории · виртуальные счёта-цели · мультивалютность · семейный доступ · тэги

## 4. Технические требования

### 4.1 Платформа
- **Хостинг**: GitHub Pages; **домен**: https://money.vitalik.dev
- **CI/CD**: GitHub Actions (авто-деплой при пуше в `master`), тесты блокируют деплой
- **PWA**: офлайн-режим (Этап 7)

### 4.2 Фронтенд
- **Язык**: TypeScript
- **Фреймворк**: **Preact 10 + preact/compat** (настоящий React исключён через shim-пакеты `vendor/`)
- **Экосистема**: react-router-dom 7 и zustand через shim; собственный `MoneyInput`
- **Бандлер**: Vite; **стили**: Tailwind CSS v4
- **AI-assisted development**: opencode.ai

### 4.3 Бекенд и данные
- **Backend-абстракция** (`src/lib/backend/`): интерфейсы `Backend`/`AuthProvider`/`Repository`,
  адаптеры `firestore` (production) и `local` (dev, localStorage), драйвер по `VITE_STORAGE_DRIVER`
- **База данных**: Firebase Firestore (free tier); **аутентификация**: Firebase Auth
- **Офлайн**: PWA + локальное кэширование

### 4.4 Ограничения free tier Firebase
- 1 GB хранимых данных, 10 GB/мес загрузок, 50k reads/day, 20k writes/day, 10 MB/request

## 5. Ограничения по реализации

- Только ручной ввод (нет автоматической синхронизации с банками)
- Однопользовательский режим (семейный доступ — post-MVP)
- Локализация — русский; валюта — RUB (мультивалютность — post-MVP)
- Личный проект: без онбординга, партнёрки, маркетинга
- UI адаптивный на каждом этапе

## Вопросы и противоречия

> Вопросы ниже закрыты с принятыми решениями. Оставлены для истории.

- ✅ **План vs Факт**: `mode` определяет поведение. План-транзакции не влияют на баланс счетов — только на прогноз Резервов.
- ✅ **Регулярные транзакции**: в MVP реализуем сами (ХаниМани: «Всегда» или «Повторять до», правка «Только эту / Эту и будущие»); Cloud Functions не нужны.
- ✅ **Мобильный UI**: не делается отдельный — адаптивная вёрстка на каждом этапе.
- ✅ **Онбординг/партнёрка**: исключены — софт личный.
